# ADR-004 — BullMQ para filas de notificações
**Data:** Abril 2026 | **Status:** Aceito

## Contexto
O sistema precisa disparar e-mails em momentos futuros (lembrete 24h antes, 2h antes) com retry automático em caso de falha. Isso exige um sistema de filas persistente.

## Decisão
Usar **BullMQ** sobre **Redis**.

## Consequências
✓ Jobs persistidos no Redis — sobrevivem a restart do servidor  
✓ Retry com backoff exponencial nativo  
✓ Cron jobs para tarefas recorrentes (reset de quota mensal, verificação de trial)  
✓ Dashboard via Bull Board para monitorar filas em produção  
✓ Redis já necessário para cache — sem infraestrutura adicional  
✗ Dependência de Redis em produção  
✗ Complexidade adicional vs envio síncrono  

## Alternativas consideradas
- **node-cron + envio síncrono**: simples mas sem persistência — perde jobs em restart
- **Agenda (MongoDB)**: requereria MongoDB além do PostgreSQL
- **Serviço externo (Inngest, Trigger.dev)**: boa DX mas custo adicional e dependência externa
