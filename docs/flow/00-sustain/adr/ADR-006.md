# ADR-006 — Arquitetura modular em camadas (não Clean Architecture pura)
**Data:** Abril 2026 | **Status:** Aceito

## Contexto
Precisamos de uma arquitetura organizada, mas que seja produtiva para solo dev. Clean Architecture pura (com casos de uso, portas, adaptadores, entidades de domínio separadas) adiciona muita cerimônia para um time de um.

## Decisão
Adotar **arquitetura modular em camadas por domínio**, com separação routes → service → repository, aplicando princípios SOLID e Clean Code sem a estrutura completa da Clean Architecture.

## Estrutura
```
módulo/
├── módulo.routes.ts      # HTTP, validação de entrada
├── módulo.service.ts     # regras de negócio
├── módulo.repository.ts  # queries ao banco
└── módulo.schema.ts      # schemas Zod
```

## Consequências
✓ Produtividade alta — menos arquivos por feature  
✓ Fácil de entender para colaboradores futuros  
✓ Separação de responsabilidades suficiente para o porte do projeto  
✓ Testável — service pode ser testado sem HTTP, repository pode ser mockado  
✓ Evoluível — pode migrar para Clean Architecture em módulos específicos se necessário  
✗ Sem inversão de dependência formal — services importam repositories diretamente  
✗ Pode escalar para complexidade se o negócio crescer muito  

## Alternativas consideradas
- **Clean Architecture completa**: ideal para times grandes, mas overhead alto para solo dev
- **MVC tradicional (controllers + models)**: simples mas mistura regras de negócio com HTTP
- **Hexagonal (ports & adapters)**: elegante mas verboso para MVP
